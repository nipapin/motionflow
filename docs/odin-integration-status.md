# Odin → Motionflow: выполнено 30 сентября 2026

Состояние ниже — история подготовки. **1 октября 2026 каталог подключён на рабочем Odin**:
четыре новых Full/Demo-пака привязаны и опубликованы. Текущие настройки и проверки:
[подключение паков 1 октября](./odin-connected-2026-10-01.md).

## База и управление

- Применена `2026_09_30_002_motionflow_management.sql`: новые таблицы
  `odin_motionflow_access`, `odin_motionflow_audit` и индекс. Существующие таблицы,
  аккаунты и платёжные подписки не переписывались и не удалялись.
- Подготовлены поиск пользователей, просмотр подписок, приглашённых мест и CEP-устройств;
  временный доступ, блокировка CEP, возврат к подписке и отзыв устройства с журналом.
- Ручное правило доступа отделено от `next_charge_date`, которую обновляет оплата.
- Реальное чтение API проверено: 25 пользователей на странице, детали аккаунта доступны.
  Изменения доступа реальным пользователям не выполнялись. Транзакции и аудит проверены тестами.
- Защита изолированных HTTP endpoints: без секрета Odin возвращает 401;
  Motionflow без администраторской сессии возвращает 403.

## Код и окружения

- Прошли 37 тестов: Motionflow 10, Odin 17, CEP Odin 10.
- Обе production-сборки успешно выполнены в отдельных каталогах сервера.
- Дополнительно исправлена несовместимость генератора ZIP-диффов с установленным
  `archiver` 8; регрессионный тест создаёт настоящий ZIP.
- Изолированная копия: `/var/www/motionflow_p_usr/data/www/.odin-integration-20260930`.
  Preview Motionflow слушает только `127.0.0.1:13301`, Odin — `127.0.0.1:13302`.
  Связь этих production-сборок с настоящими БД и R2 проверена чтением.
- Локальные dev-серверы: Motionflow `127.0.0.1:3301`, Odin `127.0.0.1:3302`.
- Секреты сохранены в игнорируемых `.env.local`, не в документации или Git.
  На тестовых копиях управление включено, `MOTIONFLOW_CATALOG_ENABLED=false`.
- Рабочие PM2-приложения не заменялись и не перезапускались; live env не изменены.
  Поэтому новый интерфейс пользователей на публичном Motionflow ещё не развёрнут.
- Снимки исходников включают текущие локальные изменения проектов. Перед live rollout
  сверить состав с рабочими сайтами, сохранить резервную копию кода/сборок/env и подготовить откат.

## Следующие конкретные шаги

1. Согласовать выкладку управления пользователями, оставив каталог Odin прежним.
   Развернуть проверенный код и парные секреты, включить только управление.
   Миграция уже выполнена: повторное создание таблиц не требуется.
2. Войти администратором в Packages → Odin → Users, проверить поиск и карточку.
   Выбрать тестовый аккаунт для проверки команд доступа и отзыва устройства.
3. Установить подготовленные полные ZIP в новой панели на тестовом Adobe-проекте:
   AE и PR, превью, шрифты, применение разных типов ресурсов, переустановка/обновление.
   Проверить пригодность JSON Test Mode для выпуска и требования версий приложений.
4. Подготовить демопаки. На сервере есть два старых demo ZIP, но их `.odin` бинарные;
   нужен исходный JSON или отдельно проверенная конвертация. Полные паки не выдавать как демо.
5. После успешной проверки опубликовать проекты 11/12, настроить точный
   `MOTIONFLOW_DOWNLOAD_HOSTS` и проверить каталог/скачивание сначала на тестовой копии.
   Затем согласовать `MOTIONFLOW_CATALOG_ENABLED=true` на рабочем Odin.
6. Публикацию новой CEP/ZXP и `latest.json` выполнять отдельно после проверки Adobe.

Повторяемые команды, семантика доступа и откат описаны в
[runbook](./odin-integration-runbook.md). Кэш подготовки лежит в
`next-app/.cache/odin-migration`; он не включается в Git.
