# Письмо Gal Toolkit MAX: переустановка пака 1.3.3

Готовое сервисное письмо на английском. Отправка не выполнялась. Письмо предлагает удалить пак кнопкой корзины, подтвердить удаление и снова установить его через кнопку скачивания. Ручное удаление папок не требуется в инструкции. Отдельно указано: процедуру нужно пройти даже при версии 1.3.3 в панели, а для Premiere Pro и After Effects — в каждом используемом приложении.

## Файлы

- `preview.html` — локальный предпросмотр с картинками; не использовать как тело отправляемого письма.
- `email.html` — самостоятельная HTML-версия со встроенными картинками для открытия в браузере. Работает без отдельной папки изображений; не использовать как тело отправляемого письма.
- `galtoolkit-133-reinstall.html` — копия самостоятельной HTML-версии.
- `email-mailgun.html` — HTML для Mailgun, изображения подключены через `cid:` и inline-вложения.
- `email.txt` — текстовая версия.
- `subject.txt` — тема: **Gal Toolkit MAX 1.3.3: reinstall your toolkit package**.
- `email.json` — поля `subject`, `text`, `html`.
- `images/` — три иллюстрации интерфейса и логотип, обязательные inline-вложения.
- `mailgun-message.mjs` — сборка FormData для одного получателя без сетевого запроса и без отправки.
- `preview-desktop.png`, `preview-mobile.png` — проверенная вёрстка на ширине 860 и 390 px.

## Как использовать в Mailgun

1. Открыть `email.html`, проверить текст и выбрать существующий подтверждённый адрес отправителя Premiere Gal. Если указать Reply-To, использовать реальный обслуживаемый адрес поддержки.
2. Подставить `subject`, `text`, `html` из `email.json` в multipart-запрос Mailgun Messages API. Нельзя передавать этот JSON целиком как JSON-тело API: он содержит только шаблон письма.
3. Добавить **четыре** поля `inline`, по одному для каждого PNG из `images/`, сохранив имена файлов. Просто загрузить HTML в редактор шаблона недостаточно: ссылки `cid:` требуют inline-вложений при отправке. Их не надо публиковать на сайте или загружать в R2.
4. Сначала отправить одно письмо на свой тестовый адрес. В реальном почтовом клиенте проверить все четыре изображения и ссылку на FAQ. Браузерный предпросмотр уже проверен; доставку и отображение в Gmail/Outlook нужно проверить тестовым письмом.
5. Для рассылки использовать список пользователей Gal Toolkit MAX. Передавать одного получателя в каждом запросе, либо реализовать стандартную персонализацию batch API отдельно. Готовый модуль собирает письмо для одного адреса и защищает от случайного раскрытия общего списка через To.

Сборка тела запроса в существующем коде рассылки (Node.js 20+):

```js
import { buildMailgunMessage } from './mailgun-message.mjs';

const body = buildMailgunMessage({
  from: verifiedPremiereGalSender,
  to: recipientEmail,
  replyTo: supportReplyAddress,
});
// Передайте body существующему отправителю Mailgun.
// Модуль сам не обращается к API и не считывает ключи или список пользователей.
```

Официальный формат inline-вложений: [Mailgun: Send with Attachments](https://documentation.mailgun.com/docs/mailgun/user-manual/sending-messages/send-attachments).

Не использовать для этой рассылки существующий `scripts/send-campaign-queued.mjs` без адаптации: он содержит другую кампанию FLOW10, её аудиторию и состояние очереди. Раздел выдачи доступа `/profile/campaigns` также не предназначен для этого сервисного уведомления: его процесс изменяет доступ пользователей и работает через Resend.

## Источник иллюстраций и проверки

Это снимки **изолированно отрендеренных компонентов** установленного расширения `Gal Toolkit Max Beta`: `design/profile.html`, оригинальные CSS/иконки, класс Popup и обработчик Remove Package из `js/events.js`. Это не скриншоты рабочего сеанса Premiere и не подтверждение успешной переустановки пака. Использовано демонстрационное состояние версии 1.3.3, без личных данных аккаунта. Реальные настройки и файлы пака не менялись. В письме изображения названы interface illustrations.

Генератор `build.mjs` использует оригинальные компоненты, а не рисует похожий интерфейс. Он работает локально с установленным расширением и Playwright из рабочего runtime; при переносе пути можно задать через `GAL_EXTENSION_PATH` и `CODEX_NODE_MODULES`. Повторная сборка перезаписывает файлы письма и иллюстрации.
