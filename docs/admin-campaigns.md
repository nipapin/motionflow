# Админка: Кампании

Раздел `/profile/campaigns` доступен тем же администраторам, что и `/profile/users`. В боковое меню добавлен пункт «Кампании».

## Создание и запуск

1. Создать кампанию, выбрать сайт для входа и вид выдачи: приглашение, подписка на месяц/год или конкретный товар на месяц/год/бессрочно.
2. Загрузить CSV/TXT или вставить email по одному на строку. CSV: `Email,First Name,Last Name`; необязательный `Account Email` позволяет отправить уведомление на другой адрес существующего аккаунта. Для нового аккаунта письмо отправляется на его адрес. Максимум 5000 получателей; одинаковые строки объединяются, конфликтующие записи отклоняются.
3. Загрузить письмо в JSON (`subject`, `text`, `html`) либо HTML, затем проверить тему и текстовую версию. Для Premiere Gal есть предустановка двух готовых писем: основного и о продлении.
4. Сохранить и нажать «Проверить и посмотреть письма». Проверка не создаёт аккаунты и не изменяет доступ/Paddle. Для каждого получателя рассчитывается итоговая дата, выбирается подходящий шаблон. В предпросмотре ссылки содержат `PREVIEW_ONLY`.
5. Нажать «Выдать доступ». Перед фактической выдачей даты пересчитываются по текущим данным. Неизвестные аккаунты создаются автоматически с недоступным случайным паролем. Существующие аккаунты и Google-вход сохраняются.
6. После окончания выдачи нажать «Отправить письма». Персональные ссылки установки пароля создаются здесь: криптографический токен 64 hex-символа, bcrypt-хеш в таблице сброса пароля, срок 7 дней. Существующие аккаунты получают обычную ссылку на сайт. Отправка блокирует тестовые токены и нераскрытые переменные.

Для действующей подписки дополнительный срок отсчитывается от самой поздней даты окончания текущего доступа или оплаченного периода, включая отменённую подписку с оставшимся оплаченным временем. Для истёкшего доступа срок отсчитывается от момента выдачи. Бессрочный доступ не сокращается.

Активный тариф продлевается в рамках того же уровня: например, Creator + AI нельзя незаметно заменить на Creator. Если выбрано другое семейство тарифа, проверка останавливается и предлагает выбрать текущий тариф либо отдельно разобрать его изменение.

## Перенос списаний Paddle

Для действующей рекуррентной подписки сервер получает актуальный период из Paddle и переносит следующее списание до окончания бонусного доступа с `proration_billing_mode: do_not_bill`. Отменённые и приостановленные подписки не возобновляются. Trial, задолженность, неизвестные/смешанные товары, запланированные изменения и списание менее чем через 30 минут останавливают обработку для ручного разбора. Бессрочный аккаунт с продолжающимися списаниями также требует ручного разбора.

Среда (`sandbox`/`production`) фиксируется при сохранении кампании и проверяется при обработке. Ключи и цены должны соответствовать выбранной среде. Кампании Spunkram используют отдельные настройки `SPUNKRAM_PADDLE_API_KEY` и `NEXT_PUBLIC_SPUNKRAM_PADDLE_ENVIRONMENT`.

Локальная выдача и внешнее изменение Paddle являются отдельными шагами: при ошибке Paddle локальный доступ может уже быть выдан, но отправка писем остаётся заблокированной. Повторный запуск продолжает синхронизацию по журналу, проверяя уже установленную дату; ещё один месяц/год не добавляется.

## Продолжение после ошибок

Обработка идёт по одному получателю на запрос. Закрытие страницы или кнопка остановки завершает текущий шаг и останавливает следующие; автоматической фоновой очереди в этой версии нет. Статусы и ошибки сохраняются в БД, кампанию можно открыть и продолжить.

Внутри кампании выдача и отправка повторяемы без дубликатов. Другая новая кампания считается отдельной выдачей. После начала выдачи конфигурация и получатели неизменяемы. До запуска можно вернуть проверенную кампанию в черновик.

Перед запросом к Resend сохраняются точный текст сообщения и ключ идемпотентности. При потере ответа повторяется то же сообщение. Если неопределённость длится 23 часа или больше, автоматический повтор блокируется: сначала нужно проверить сообщение в Resend, поскольку его окно идемпотентности ограничено. `Принято Resend` означает принятие провайдером; доставку, bounce и открытия этот раздел пока не отслеживает.

## Доступ к товарам

Выдачи хранятся в `sold_items` с `system='campaign'`; дата — `arguments.access_expires_at`. Проверки скачивания, владения, purchase-code и доступа CEP в Next.js учитывают срок без cron-задачи. Старые покупки и постоянные выдачи не меняются. Если отдельно работает старый Laravel/PHP download API, туда нужно перенести ту же проверку перед использованием ограниченных по времени выдач через этот API.

## Установка и проверки

Новые таблицы `admin_campaigns` и `admin_campaign_recipients` создаются при первом разрешённом обращении к разделу из миграции `db/migrations/2026_10_08_admin_campaigns.sql`. Если production DB-пользователь не имеет CREATE, миграцию нужно применить отдельно. Новые зависимости не нужны. Для рассылки нужны `RESEND_API_KEY`, разрешённый отправитель (`MAIL_FROM_ADDRESS` / текущая конфигурация mailer) и публичный работающий reset-password на выбранном сайте.

```powershell
node scripts/test-admin-campaigns.mjs
node --env-file=.env scripts/test-admin-campaigns.mjs --database
npx tsc --noEmit --incremental false
```

Интеграционный режим использует только временные таблицы одной MySQL-сессии. Paddle/Resend заменены тестовыми сервисами: настоящие аккаунты, подписки и письма не меняются.
