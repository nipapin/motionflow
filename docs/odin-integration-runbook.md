# Odin → Motionflow: подготовка и запуск

## Статус

Обновлено 30 сентября 2026: миграция управления применена, создан и проверен
приватный клон `motionflow-odin`, подготовлены и загружены полные JSON-паки AE/PR.
В Motionflow созданы скрытые проекты AE **11** и PR **12**, автор Odin использует новый бакет.
Код собран и проверен в изолированном окружении на рабочем сервере.
Рабочие приложения не перезапускались, каталог не переключён. Новые секреты
настроены только локально и в изолированном окружении; live env не изменены.
Подробные результаты и оставшиеся шаги: [статус выполнения](./odin-integration-status.md).
Настройки путей к распакованным пакам не расширяются: Odin переходит на общий формат.

Odin сохраняет свой сайт, PostgreSQL, аккаунты, вход, PayPro и подписки.
Motionflow управляет пак-проектами в своей админке и обращается к защищённому
API Odin для поиска пользователей, просмотра подписок и управления доступом к CEP.
Пароли, токены входа и хеши устройств не передаются в Motionflow.

## 1. Подготовить общий формат паков

1. Выгрузить исходные папки `odin-pro/` и `odin-pro-ae/` в разные локальные рабочие каталоги.
2. Получить релизные JSON-описания `.odin` для PR и AE. Не переименовывать бинарный файл в JSON.
   Нужны `settings` и одно из `structure`, `contents`, `content`.
3. Заменить старые бинарные описания новыми. Оставить одно основное `.odin` на пакет.
4. Сохранить внутренние относительные пути ресурсов, проверить наличие всех файлов,
   превью, шрифтов и ссылок из описания. Не переименовывать внутренние папки без изменения ссылок.
5. Сверить `settings.main.name`, `version`, `software_id` и требования версий с проектом админки.
   Имена для сохранения совместимости:
   `Odin Pro for After Effects` и `Odin Pro for Premiere Pro`.
6. Пересоздать `manifest.json`: массив `{name, path, size, hash}`.
   `path` — относительно корня пака, разделитель `/`; `hash` — SHA-256 байтов файла.
   Включить новый `.odin` и ресурсы. Сам manifest не хешировать в себя.
   Не использовать R2 ETag вместо SHA-256.
7. Создать ZIP из **содержимого** папки пака, без дополнительной внешней папки.
   `manifest.json` и `.odin` должны лежать в корне ZIP.
8. Проверить локальную установку и применение ресурсов новой панелью в AE и PR.

Пример согласованной раскладки в НОВОМ приватном бакете `motionflow-odin`:

```text
secure/packages/900000001/12/odin-pr-1.2.0.zip
odin-pr-1.2.0/
  manifest.json
  Odin Pro for Premiere Pro.odin
  Assets/...
  Previews/...
  Fonts/...

secure/packages/900000001/11/odin-ae-1.2.0.zip
odin-ae-1.2.0/
  manifest.json
  Odin Pro for After Effects.odin
  Assets/...
  Previews/...
  Fonts/...
```

**Важно:** существующий `resolvePackContentStem()` берёт basename ZIP без `.zip`.
Поэтому распакованные папки лежат в **корне бакета**, даже когда ZIP находится в `secure/...`.
Не использовать одинаковое имя ZIP для разных паков/версий.

## 2. Создать копию и загрузить релизы

После согласования создать приватный бакет `motionflow-odin` в том же аккаунте R2.
Настроить `rclone` remote `r2` на существующий S3 endpoint и ключи; не писать ключи в команды/документацию.

Предварительная проверка копирования, затем копирование без удаления объектов:

```powershell
rclone copy r2:odin-pro r2:motionflow-odin --dry-run
rclone copy r2:odin-pro r2:motionflow-odin --progress
rclone check r2:odin-pro r2:motionflow-odin --one-way --download
```

Последняя команда читает содержимое для проверки, поэтому занимает время и трафик.
Оригинальный `odin-pro` остаётся источником старого сайта/старой панели.
Rclone копирует объекты, но не CORS, домены и правила доступа бакета.
Приватные архивы не публиковать через публичный домен; сервер выдаёт временные GET URL.
Превью карточек загружать штатно через Motionflow в его публичный бакет.

Затем загрузить подготовленные ZIP и распакованные папки из пункта 1.
Пример (подставить существующий ID проекта, пути и версию):

```powershell
rclone copyto 'D:/Odin/releases/odin-pr-1.2.0.zip' 'r2:motionflow-odin/secure/packages/900000001/<PR_PROJECT_ID>/odin-pr-1.2.0.zip' --progress
rclone copy 'D:/Odin/releases/odin-pr-1.2.0' 'r2:motionflow-odin/odin-pr-1.2.0' --progress
```

Большие ZIP не загружать через веб-форму: её текущий лимит 4 MB.
Допустим также R2Sync. Веб-привязка не распаковывает ZIP.

## 3. Настроить проекты в Motionflow

1. Packages → Authors → Odin: выбрать новый бакет. До согласования не менять рабочую запись.
2. Создать два скрытых проекта: AE и PR; записать их числовые ID.
3. Заполнить имя, версию, host, превью и требования к приложениям.
4. Bind from R2: выбрать соответствующий ZIP. Проверить чтение структуры по manifest.
5. Не привязывать к marketplace item: Odin — внутренний автор паков `900000001`.
6. Включить видимость только после проверки файлов. Для выдачи через интеграцию `admin_only` должен быть выключен.
7. На один host должна быть одна видимая полная версия; необязательная отдельная демоверсия имеет `version=DEMO`.
   Старые версии хранить в R2, но скрывать в каталоге при публикации новой.

## 4. Настроить серверное соединение

Создать **два разных** случайных секрета, каждый не короче 32 символов.
Хранить их только в серверном окружении; не использовать `NEXT_PUBLIC_...`.

В `next-app`:

```dotenv
ODIN_MANAGEMENT_ORIGIN=https://odin-pro.com
ODIN_MANAGEMENT_SECRET=<секрет управления пользователями>
ODIN_CATALOG_SECRET=<отдельный секрет каталога>
ODIN_CATALOG_PACK_MAP={"283":<AE_PROJECT_ID>,"275":<PR_PROJECT_ID>}
```

Значение карты должно стать валидным JSON с реальными числовыми ID вместо плейсхолдеров.
Это соответствие старого ID Odin новому ID проекта Motionflow.
Оно сохраняет идентичность установленных паков. Смена ZIP/версии того же проекта не требует менять карту.
Непривязанные проекты, скрытые проекты и `admin_only` не выдаются.

В `ione-premiere-basics`:

```dotenv
MOTIONFLOW_MANAGEMENT_SECRET=<тот же секрет управления пользователями>
MOTIONFLOW_MANAGEMENT_ENABLED=false
MOTIONFLOW_CATALOG_ORIGIN=https://motionflow.pro
MOTIONFLOW_CATALOG_SECRET=<тот же секрет каталога>
MOTIONFLOW_CATALOG_ENABLED=false
MOTIONFLOW_DOWNLOAD_HOSTS=<точный hostname подписанных URL нового бакета>
```

Hostname брать из реально подписанного URL нового бакета, без схемы и пути.
Не переносить автоматически hostname старого бакета. При необходимости несколько hostname разделять запятыми.
HTTP origins разрешены только для localhost/127.0.0.1, в том числе при размещении обоих сайтов на одном сервере.
Для соединения между серверами требуется HTTPS.

Доступ к админке по-прежнему контролирует `PACKAGES_ADMIN_EMAILS`.
Сотрудникам Odin не выдавать этот общий доступ без отдельного решения: сейчас это права на всех авторов.

## 5. Включить пользователей отдельно от каталога

**Этот шаг изменяет рабочую базу/поведение и требует согласования перед выполнением.**

1. Развернуть подготовленный код Odin с обоими флагами `false`.
2. Применить миграцию `2026_09_30_002_motionflow_management.sql` штатным `npm run migrate`.
   Перед запуском проверить список ожидающих миграций: runner применяет все ожидающие файлы.
   Новые таблицы — `odin_motionflow_access`, `odin_motionflow_audit`; финансовые таблицы не меняются.
3. Развернуть Motionflow с настройками соединения.
4. Установить на Odin `MOTIONFLOW_MANAGEMENT_ENABLED=true`, перезапустить приложение.
5. Packages → Odin → Users: проверить поиск реального аккаунта, подписку, приглашённые места и CEP-устройства.
6. На согласованном тестовом аккаунте проверить Grant → Block → Use subscription; отзыв одного устройства.
   Подтвердить наличие записей журнала и неизменность оплаты.

Смысл команд:
- Grant: временный доступ к расширению; после даты снова действует подписка Odin.
- Block: запрет платного доступа к CEP даже при активной подписке. Оплата не отменяется.
- Use subscription: удалить ручное правило.
- Revoke device: отозвать текущую CEP-сессию; пользователь может войти снова.

Это не удаление аккаунта и не изменение PayPro-подписки.
Доступ переоценивается при запросах к серверу/обновлении профиля; скачанные файлы не удаляются.
Ранее выданный подписанный URL действует до своего срока (до 10 минут).
Устройства старого AtomX не смешиваются с новой таблицей `odin_cep_devices`.

## 6. Переключить каталог отдельно

**Включать только после готовности обоих паков и согласования.**

1. Проверить защищённые Motionflow endpoints `/api/integrations/odin/catalog` и `/download?pack_id=283|275`.
2. Убедиться, что в каталоге старые ID, правильные hosts/версии, а URL ведут в новый приватный бакет.
3. На тестовом окружении Odin включить `MOTIONFLOW_CATALOG_ENABLED=true`.
4. Проверить: вход подписчика и неподписчика; чистая установка AE/PR; обновление установленного пака;
   распаковка, превью, шрифты и применение ресурсов; закрытие доступа после Block.
5. Если есть DEMO: отдельный JSON-пак и отдельный ID в карте; доступ только к его архиву без подписки.
6. После проверки включить флаг на рабочем Odin. Старый CEP и legacy package server не переключаются этим кодом.

При включённом флаге каталог и signed download URL получает **сервер Odin**, проверивший аккаунт/доступ.
CEP продолжает обращаться к `odin-pro.com`, секреты интеграции в расширение не попадают.
Первый запуск использует полные ZIP; `/market/diff` отдаёт `NO_DIFF_SOURCE`, новая панель переходит к полной загрузке.
Автоматического перехода к старому каталогу при ошибке нет, чтобы не смешивать версии и форматы.

## Откат

- Каталог: `MOTIONFLOW_CATALOG_ENABLED=false` возвращает существующий AtomX/package.odin-pro.com путь.
  Старые бинарные `.odin` при этом всё ещё не подходят новой панели: откат источника не исправляет формат.
- Управление доступом: `MOTIONFLOW_MANAGEMENT_ENABLED=false` возвращает штатную проверку подписки;
  ручные блокировки/выдачи перестают действовать. Уже отозванные устройства не восстанавливаются.
- Таблицы журнала, старые объекты и новые версии не удалять.
