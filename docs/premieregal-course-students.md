# Год Gal Toolkit MAX для участников курса

Реализован отдельный скрипт `scripts/premieregal-course-students.mjs`. Он ничего не запускает при импорте. По умолчанию выполняется только проверка CSV без подключения к базе и почте. Создание таблиц журнала, выдача доступа, перенос списаний Paddle и отправка писем — отдельные команды, которые нужно запускать явно.

## Правила обработки

- Источник участников — переданный CSV. Ответы в колонках о наличии и типе подписки справочные: фактическое состояние проверяется в базе.
- Аккаунт ищется по колонке `What email did you use to sign up for the Gal Tookit MAX?`; если она пуста, используется `Email`. Адреса приводятся к нижнему регистру, пробелы по краям удаляются.
- Письмо отправляется на `Email`. Если два адреса соответствуют разным аккаунтам или указанный отдельный адрес аккаунта не найден, обработка останавливается для ручной проверки. Скрипт не объединяет аккаунты.
- Отсутствующий аккаунт создаётся со случайным паролем, который не сохраняется в открытом виде. Подтверждение почты происходит при установке пароля через существующий механизм приглашений.
- Без действующей подписки выдаётся год доступа от даты выполнения. При действующей подписке берётся более поздняя дата из `ends_at` и `paddle_billing_period_ends_at` всех действующих подписок PremiereGal; к ней добавляется календарный год. Отменённая подписка с ещё действующим оплаченным периодом также учитывается. 29 февраля переходит в 28 февраля следующего года.
- Дополнительный доступ создаётся отдельной бесплатной записью `system = admin`, `plan = yearly`, автор `4141`. Для существующих возобновляемых подписок отдельный этап `billing-apply` переносит дату списания непосредственно в Paddle на год от окончания текущего периода. Цена, состав тарифа и периодичность следующих платежей сохраняются. Подписки других авторов не учитываются.
- Действующий бессрочный доступ сохраняется; письмо участнику всё равно предусмотрено.
- Одинаковые дубли CSV объединяются, конфликтующие дубли отклоняются. Журнал в базе не даёт повторно добавить год одному аккаунту в рамках той же кампании, даже после перестановки строк CSV.
- Аккаунт, доступ и запись журнала сохраняются в одной транзакции для каждого участника. При ошибке скрипт останавливается; ранее завершённые участники сохраняются. Повторный запуск продолжает обработку. Ошибки предварительной проверки всего списка останавливают выдачу до начала изменений.

## Команды

Нужен Node.js **22.18+** с поддержкой импорта TypeScript; дополнительные зависимости не добавлены. Переменные базы берутся из окружения и корневого `.env`: `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD`, `DB_DATABASE`.

Ниже команды для будущего ручного запуска. При разработке выполнялись только автономные тесты и `validate`.

В PowerShell сначала можно указать путь:

```powershell
$courseCsv = '.campaigns/course-students.csv'
```

Проверка формата CSV, без базы и рассылки:

```powershell
node scripts/premieregal-course-students.mjs validate --csv "$courseCsv"
```

План по фактическим аккаунтам и подпискам — только чтение базы. Может выполняться до создания журнала:

```powershell
node scripts/premieregal-course-students.mjs preview --csv "$courseCsv"
```

Явное создание таблиц журнала из `db/migrations/2026_10_08_premieregal_course_grants.sql` и `db/migrations/2026_10_08_premieregal_course_billing.sql`. Эта команда не создаёт аккаунты и доступ. Если `init` уже выполнялся до добавления этапа Paddle, его можно повторить для создания второго журнала:

```powershell
node scripts/premieregal-course-students.mjs init
```

Выдача доступа и создание недостающих аккаунтов. Писем эта команда не отправляет:

```powershell
node scripts/premieregal-course-students.mjs apply --csv "$courseCsv"
```

Идентификатор кампании по умолчанию: `premieregal-course-free-year`. Для всех этапов одного списка он должен оставаться одинаковым. Не меняйте `--campaign` для повторного запуска: новый идентификатор означает новую выдачу года. Один процесс обработки кампании блокирует второй через MySQL advisory lock. Для записи требуются таблицы InnoDB.

## Перенос billing date в Paddle

После `apply` скрипт читает реальные подписки PremiereGal из Paddle по сохранённым в базе `sub_...`. Новая дата вычисляется **от `current_billing_period.ends_at` Paddle**, а не от сегодняшней даты или уже продлённого бесплатного доступа. Например, `2027-01-15` переходит в `2028-01-15` с сохранением времени. Для месячного тарифа после отложенного списания остаётся месячная периодичность.

Нужны `PADDLE_API_KEY` с доступом чтения и изменения подписок и явно заданная `NEXT_PUBLIC_PADDLE_ENVIRONMENT=sandbox` или `production`. Используется основной аккаунт Paddle проекта, в котором находятся подписки PremiereGal.

Просмотр исходных и новых дат, только чтение базы и Paddle:

```powershell
node scripts/premieregal-course-students.mjs billing-preview --csv "$courseCsv"
```

Явное применение переноса и синхронизация подтверждённого срока в локальной базе:

```powershell
node scripts/premieregal-course-students.mjs billing-apply --csv "$courseCsv"
```

Запрос содержит только `next_billed_at` и `proration_billing_mode: do_not_bill`. Такой [режим Paddle переносит дату без доплаты или кредита за дополнительный период](https://developer.paddle.com/build/subscriptions/change-billing-dates/). Цена, количество, тариф и другие поля в запрос не включаются. Скрипт также поддерживает перенос окончания действующей пробной подписки.

Перед изменениями проверяется весь список. Подписки с задолженностью, запланированной отменой/паузой/сменой, неизвестным составом продуктов, неверным владельцем или списанием в ближайшие 30 минут останавливают этап для ручной проверки. Старые идентификаторы Paddle Classic также требуют ручной проверки. Уже отменённые или приостановленные подписки не возобновляются: переносить очередное списание у них не требуется, дополнительный локальный год доступа остаётся.

Журнал `premieregal_course_billing` хранит окружение, исходную дату и **фиксированную новую дату до запроса в Paddle**. После подтверждения обновляются сроки платной подписки, резервного бесплатного доступа и срок для будущего письма. Если ответ Paddle потерялся или база не сохранила результат, повторный запуск сначала читает Paddle: при уже установленной новой дате выполняется только синхронизация базы. Ещё один год не добавляется. Неожиданная смена даты, тарифа, владельца или окружения останавливает обработку.

SQL-транзакция не удерживается во время HTTP-запроса в Paddle. Изменение Paddle и базы не является общей атомарной операцией; сохранённый журнал обеспечивает восстановление после частичного выполнения. Проверка всего списка происходит до первого изменения, но последующий сетевой сбой может оставить часть участников завершёнными — повторять нужно ту же кампанию.

## Письмо для участников курса

Готовый английский шаблон: `docs/email-templates/premieregal-course.json`. Он содержит тему, текстовую и HTML-версии. Тема: **Your free year of Gal Toolkit MAX is ready**. В письме указаны год доступа без дополнительной оплаты, срок доступа и email для входа.

Второй шаблон для существующих аккаунтов с продлённой подпиской: `docs/email-templates/premieregal-course-extension.json`. Тема: **Your Gal Toolkit MAX subscription has been extended by one year**. Письмо объясняет, что бесплатный год начинается после окончания текущего периода, и показывает итоговую дату доступа. Пользователь входит обычным способом через кнопку **Open Gal Toolkit MAX**.

Для смешанного списка укажите оба файла: основной через `--template`, второй через `--extension-template`. Скрипт выбирает второй вариант только для существующих аккаунтов с результатом `extend_access` в журнале и конечной датой доступа. Существующий аккаунт без действующей подписки получает основной вариант; бессрочный доступ также не описывается как продление на год. Без `--extension-template` сохраняется прежнее поведение. Пример предварительного просмотра (без отправки):

```powershell
node scripts/premieregal-course-students.mjs mail-preview --csv "$courseCsv" --template 'docs/email-templates/premieregal-course.json' --extension-template 'docs/email-templates/premieregal-course-extension.json' --site-origin 'https://premieregal.motionflow.pro'
```

При будущей отправке используйте те же параметры с командой `send`. При повторе неизвестной отправки выбранный для этого пользователя шаблон должен совпадать с сохранённым письмом.

Оформление соответствует сайту Premiere Gal: фон карточек `#F0F1F9`, градиент `#DE7ABE → #6C14CF`, скругления и шрифт Inter с системными запасными шрифтами. Логотип и обложка загружаются с публичных адресов сайта; важный текст и кнопки остаются доступны при отключённой загрузке изображений. Используется табличная верстка с inline-стилями; в клиентах без поддержки градиента кнопка остаётся фиолетовой. Макет проверен в браузере, отдельная проверка в Gmail и Outlook пока не проводилась.

Основная кнопка для новых аккаунтов называется **Set your password** и открывает персональную ссылку `/reset-password` на сайте Premiere Gal. После установки пароля пользователь входит самостоятельно; автоматической авторизации по ссылке нет. Для существующего аккаунта кнопка **Open Gal Toolkit MAX** открывает сайт, письмо предлагает обычный пароль или Continue with Google. Внизу обеих версий есть ссылка на `https://premieregal.motionflow.pro/`. Пароли в письме не передаются.

Допустимые переменные: `{{first_name}}`, `{{last_name}}`, `{{email}}`, `{{account_email}}`, `{{expires_at}}`, `{{login_url}}`, `{{setup_password_url}}`, `{{access_url}}`, `{{access_label}}`, `{{account_instructions}}`, `{{access_summary}}`. Последние четыре выбирают ссылку, подпись кнопки, инструкцию и срок доступа для конкретного аккаунта. Данные участников экранируются в HTML. Для бессрочной подписки `expires_at` содержит `Lifetime`, а `access_summary` сообщает о сохранении бессрочного доступа.

Для нового аккаунта ссылка установки пароля автоматически добавляется в текст и HTML, если в них нет `{{setup_password_url}}` или `{{access_url}}`, ведущей на установку пароля. Она действует 7 дней. Для существующих аккаунтов `setup_password_url` пустая; их пароли не меняются. Ссылка создаётся только на этапе отправки, чтобы не истечь во время подготовки. Используется существующая таблица приложения `password_reset_tokens`; если она отсутствует, отправка остановится до отправки писем. Если ссылка истекла, пользователь может запросить новую через Forgot password.

После выдачи доступа просмотр будущих писем, без отправки и без создания реальных токенов:

```powershell
node scripts/premieregal-course-students.mjs mail-preview --csv "$courseCsv" --template 'docs/email-templates/premieregal-course.json' --site-origin 'https://premieregal.motionflow.pro'
```

HTML и текст сохраняются в игнорируемой Git папке `.campaigns/premieregal-course-free-year/preview`. Ссылки в этих предпросмотрах используют недействительный маркер `PREVIEW_ONLY`.

Явная рассылка подготовленного письма через Resend:

```powershell
node scripts/premieregal-course-students.mjs send --csv "$courseCsv" --template 'docs/email-templates/premieregal-course.json' --site-origin 'https://premieregal.motionflow.pro'
```

Нужны `RESEND_API_KEY` и `MAIL_FROM_ADDRESS`, либо явный `--from 'Premiere Gal <адрес отправителя>'`. Имя отправителя по умолчанию — Premiere Gal. Домен должен быть настроен в Resend. `--site-origin` задаёт публичный HTTPS-адрес сайта со страницей `/reset-password`; по умолчанию эта кампания использует `https://premieregal.motionflow.pro`.

При отправке нового приглашения создаётся реальный случайный токен из 32 байт (64 hex-символа); его bcrypt-хеш сохраняется в `password_reset_tokens` до запроса в Resend. Один и тот же токен подставляется в HTML и текстовую версию. `PREVIEW_ONLY` встречается только в предпросмотре. Этап отправки блокирует письма с `PREVIEW_ONLY`, `TEST_PREVIEW`, `TESTPREVIEW` (без учёта регистра) или неразрешёнными переменными `{{...}}`, включая сохранённые письма повторной попытки.

Каждому участнику отправляется отдельное письмо. Отправка начинается только после выдачи доступа всем участникам выбранного CSV и завершения переноса списаний для возобновляемых подписок Paddle. Команда `send` выполняет чтение Paddle для этой проверки; незавершённый или не синхронизированный перенос блокирует рассылку. У участников без подписок Paddle этот этап не требуется. Статус `sent` в журнале означает, что Resend принял письмо, а не подтверждённую доставку во входящие.

Отправленные письма пропускаются при повторном запуске. Перед запросом в Resend скрипт сохраняет точное письмо и статус `sending`. При неизвестном результате повторяется тот же запрос с тем же ключом: [Resend сохраняет ключи идемпотентности 24 часа](https://resend.com/docs/dashboard/emails/idempotency-keys). Скрипт допускает такой повтор в течение 23 часов от начала попытки, оставляя запас. Позже он останавливается и требует ручной проверки результата в Resend, чтобы не отправить дубль. Во время повторной попытки нельзя менять шаблон, отправителя или адрес сайта.

Журнал содержит адреса участников; пока отправка не подтверждена, `mail_payload` также содержит письмо со ссылкой установки пароля. После подтверждения отправки поле очищается. Эти данные не выводятся в отчёт или лог. Файл письма, отчёты и предпросмотры лучше хранить внутри `.campaigns`, которая уже исключена из Git.

## Проверка функционала

```powershell
node --test scripts/test-premieregal-course.mjs scripts/test-premieregal-course-billing.mjs
```

Тесты используют фиктивную базу, Paddle и почтовый клиент: формат CSV, конфликтующие адреса, год от конца подписки, бессрочный доступ, транзакции и повторная выдача, приглашения, безопасное повторение неизвестной отправки, перенос списаний без доплаты, ошибки Paddle и восстановление после сбоя синхронизации. Интеграционная проверка с настоящей базой, Paddle и Resend пока не выполнялась.
