# Captions: миграция на R2 — что нужно знать команде CEP-панели

Бэкенд каталога captions (`/api/captions`, `/api/captions/media/...`) переехал с локальной папки на диске на R2-хранилище. **URL эндпоинтов не изменились**, авторизация и формат тела запросов/ответов — тоже. В большинстве случаев панель может продолжать работать без изменений кода.

Но есть один момент, который стоит проверить в коде панели — см. «⚠️ Что может сломаться» ниже.

---

## TL;DR

- Эндпоинты те же: `GET /api/captions`, `POST /api/captions`, `GET /api/captions/media/...`.
- Менять URL / логику авторизации не нужно.
- **Проверьте**, не конкатенирует ли панель `previewImageUrl` / `previewVideoUrl` с каким-то base URL — теперь это уже полные абсолютные ссылки (см. ниже).
- Новое опциональное поле `brand` — можно игнорировать, по умолчанию используется `"gal"`, что соответствует текущему поведению.

---

## ⚠️ Что может сломаться

### `previewImageUrl` / `previewVideoUrl` теперь абсолютные CDN-ссылки

**Было:**

```json
"previewImageUrl": "/api/captions/media/Base/Base%20Caption_01/thumb.png"
```

Относительный путь — панель, скорее всего, склеивала его с базовым доменом сайта (`https://next.motionflow.pro` + путь).

**Стало:**

```json
"previewImageUrl": "https://cdn.motionflow.pro/Gal%20Captions/Base/Base%20Caption_01/thumb.png"
```

Уже полный абсолютный URL на CDN.

**Что проверить:** если в коде панели есть что-то вроде `baseUrl + item.previewImageUrl`, это теперь даст битую строку типа `https://next.motionflow.prohttps://cdn.motionflow.pro/...`. Правильно — использовать значение `previewImageUrl` / `previewVideoUrl` **как есть**, без каких-либо преобразований, напрямую в `<img src>` / `<video src>`.

Если панель и раньше просто клала строку из ответа в `src` без склейки — менять ничего не нужно, всё продолжит работать.

### `GET /api/captions/media/...` теперь редирект, а не поток байт

Старый URL вида `/api/captions/media/Base/Base%20Caption_01/thumb.png` больше не отдаёт файл напрямую — он отвечает `302 Found` с заголовком `Location`, указывающим на CDN. Оставлен только для обратной совместимости.

Это прозрачно для `<img>`/`<video>` и для `fetch`/`XHR` — они сами следуют за редиректом. Проблема может быть только если где-то в коде панели редирект специально не разрешён (`redirect: "manual"` / `follow: false`) — на практике для captions такого не встречали, но стоит перепроверить, если используется какой-то кастомный HTTP-клиент CEP (CSInterface / cep.node).

**Рекомендация:** если панель формирует эти URL сама (а не берёт готовыми из ответа `GET /api/captions`) — переходите на готовые `previewImageUrl` / `previewVideoUrl` из ответа. Это уже финальные CDN-ссылки, дополнительный редирект не нужен.

## Новое опциональное поле: `brand`

Каталог теперь может отдавать разные наборы стилей для разных продуктов (Gal / Spunkram). Пока в обоих одинаковые файлы, но это может измениться в будущем.

| `brand` | Что это |
|---------|---------|
| `gal` (по умолчанию, если поле не передано) | текущее поведение панели, ничего менять не нужно |
| `spunkram` | каталог для Spunkram-версии панели, если/когда появится |

Если панель — единая для Gal, можно **ничего не делать**: без параметра `brand` сервер отдаёт `gal`, как и раньше.

Если для панели значимо явно зафиксировать бренд (на случай, если дефолт когда-нибудь поменяется на бэкенде), можно передавать его явно:

- `GET /api/captions?brand=gal`
- `POST /api/captions` с полем `"brand": "gal"` в теле, рядом с `id` / `file` / `user`.

## Что не поменялось (для справки)

- Авторизация: session cookie либо CEP dev-identity (`user.id` / `user.email`, только non-production) — как раньше.
- Форма ответа `GET /api/captions` (дерево `categories[].captions[]`) — те же поля, тот же `id` вида `"Category/Caption Folder"`.
- `POST /api/captions` — тот же контракт (`id`, `file: "mogrt" | "aep" | "definition"`), те же коды ошибок (`401 UNAUTHORIZED`, `403 SUBSCRIPTION_REQUIRED`, `404 PROJECT_NOT_READY`).
- `POST /api/generations/captions` (Transcribe) — не затронут этой миграцией вообще.

Полная спецификация эндпоинтов — `docs/captions-api.md` в репозитории next-app.

---

## Чеклист для разработчика панели

- [ ] Проверить, что `previewImageUrl` / `previewVideoUrl` используются как готовая строка (без склейки с base URL).
- [ ] Если панель сама конструирует `/api/captions/media/...` URL — переключить на готовые `previewImageUrl`/`previewVideoUrl` из ответа `GET /api/captions`.
- [ ] Убедиться, что HTTP-клиент панели следует за `302`-редиректами (стандартное поведение `fetch`/`XHR`/`<img>`/`<video>` — обычно ничего делать не нужно).
- [ ] (Опционально) Передавать `brand: "gal"` явно, если хочется не зависеть от дефолта на будущее.

Если по чеклисту всё ОК — **никаких изменений на стороне панели не требуется**, миграция полностью прозрачна.
